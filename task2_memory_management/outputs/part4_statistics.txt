=== Page-fault statistics and algorithm comparison ===

Four algorithms are compared on identical inputs:
  FIFO   evict the oldest page                (Part 2)
  LRU    evict the least recently used page   (Part 3)
  CLOCK  second-chance; what real kernels use
  OPT    evict the page used furthest in the future - not
         implementable, but it is the theoretical lower bound

Hit ratio  = hits   / references x 100
Miss ratio = faults / references x 100   (miss = page fault)

===============================================================
OVERALL CONCLUSION
===============================================================

Summary of page faults at the frame count highlighted for each
workload (lower is better):

  Workload                              Frames  FIFO   LRU  CLOCK   OPT
  ------------------------------------  ------  ----  ----  -----  ----
  Classic teaching string               3          9    10      9     7
  Working set + streaming (realistic)   4         44    40     41    24
  Uniform random (worst case)           4         69    63     65    43

Across the three workloads measured above, LRU beat FIFO 2 time(s),
FIFO beat LRU 1 time(s), and they tied 0 time(s).

What the measurements support:
  - Neither policy is better in the abstract. Which one wins is a
    property of the ACCESS PATTERN, not of the algorithm alone, so a
    single reference string is never enough to judge them.
  - LRU's advantage appears exactly where its assumption holds: when
    a hot working set is re-read while other pages stream past, LRU
    protects the working set and FIFO evicts it purely for being old.
  - Where there is no locality to exploit, neither policy holds a
    stable lead: on the random workload above they trade places as the
    frame count changes, and every gap between them is small next to
    the gap separating both from OPT. When the difference in fault
    count is that marginal, FIFO's far lower bookkeeping cost is the
    deciding factor rather than the fault count itself.
  - Belady's anomaly (demonstrated in Part 2) is the one respect in
    which FIFO is not merely weaker but unsound: extra memory can
    increase its fault count. LRU is a stack algorithm and cannot.
  - CLOCK stayed close to LRU throughout while doing almost no work
    on a hit, which is why production kernels approximate LRU this
    way instead of implementing it exactly.
  - OPT is unimplementable, but it bounds the comparison: it shows how
    much of the remaining gap was winnable at all.
