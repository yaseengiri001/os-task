=== Encryption and decryption of sensitive files ===
Requirement 3.1(4)

Construction: ChaCha20 (confidentiality) + HMAC-SHA256 (integrity),
key derived by PBKDF2-HMAC-SHA256 with 200000 rounds.

SALARY REPORT (CONFIDENTIAL)
alice  62000
bob    58000
----

    on disk: 534656312f1801baba5a211daf99830f3587028465e507032bc9cc5b13dfffc0...
    The plaintext is not recoverable from that without the key.

2. Decrypting with the correct password
    recovered 55 bytes:

SALARY REPORT (CONFIDENTIAL)
alice  62000
bob    58000
----

3. Decrypting with the WRONG password
    AUTHENTICATION FAILED - wrong password, or the file was
    altered. Nothing was decrypted.
    Note the failure is reported by the MAC check, so no incorrect
    plaintext is ever produced or acted upon.

4. Tamper detection: flipping a single bit of the ciphertext
    byte 37: 0x90 -> 0x91 (one bit changed)
    AUTHENTICATION FAILED - wrong password, or the file was
    altered. Nothing was decrypted.
    Without the MAC this would have silently decrypted to text
    with one bit changed - a targeted edit by someone who could
    not read the file. The MAC is what makes that detectable.

5. The SAME plaintext encrypted twice must look different
    on disk: 534656315612e84d7dffd74fa5273beb2f0e229e05c54c42...
    on disk: 534656310a36ab2c8aaa3b3a5130f115adfaa139836ae12b...
    identical ciphertext? NO - each file used a fresh random salt and nonce
    This is what prevents the keystream-reuse attack that broke
    WEP: without it, XORing two ciphertexts would cancel the
    keystream and expose both plaintexts.

6. For contrast: why a Caesar cipher is not encryption
    plaintext:  "the salary figures must remain confidential and shou..."
    shifted +3: "wkh vdodub iljxuhv pxvw uhpdlq frqilghqwldo dqg vkrx..."
    Breaking it WITHOUT the key, by frequency analysis alone:
    commonest letter is 'h' -> assume it enciphers 'e'
    deduced shift: 3
    recovered:  "the salary figures must remain confidential and should never be revealed to anyone outside finance"
    Recovered in microseconds, with no key and no guessing. A
    Caesar cipher has 25 possible keys and preserves letter
    frequencies, so it obscures text without protecting it.

Summary
  Encryption defends data where permissions cannot: on a stolen
  disk, in a backup, or against root. ChaCha20 provides the
  confidentiality; HMAC-SHA256 provides the integrity WITHOUT which
  a stream cipher can be edited bit-by-bit by an attacker who
  cannot read it. The MAC is verified before anything is decrypted,
  and every file gets a fresh salt and nonce.
